# VibeCoding 前端應用開發 Skill

本 Skill 旨在標準化「由微回饋驅動的敏捷前端原型開發模式」。透過極致降低使用者的輸入阻力、強化視覺成果的及時多巴胺反饋，並搭配純原生零依賴的架構防禦，讓任何想法都能在短時間內轉化為可用、好用且能持續留存資料的產品原型。

---

## 適用情境

- **習慣養成與微型記錄器**：每日一行心得、微日記、健身打卡、隨手心情記錄、飲水打卡。
- **靈感收集與素材速記箱**：設計靈感快記、技術乾貨小卡、金句摘錄庫、代碼片段速查。
- **無痛生活追蹤工具**：零阻力記帳工具、個人行程備忘、景點餐廳實訪避坑評分卡。
- **展示型輕量社群/互動原型**：極簡社交動態牆、個人作品集卡片流、團隊微型佈告欄。

---

## 核心方法論（四心法）

1. **極致縮減輸入摩擦，杜絕空白畫布恐懼**：多提供主題選項與預設模板，不強求使用者從零填空。
2. **視覺成就感先行，以多巴胺反饋驅動行為**：成果卡片化、加入微互動與即時樂觀更新，讓每一次記錄都感到愉悅。
3. **隱性工程打底，無感持久化與環境防禦**：無伺服器環境下以 localStorage 兜底，並做好快取穿透防禦。
4. **原生純粹至上，堅持職責分離與零套件負擔**：HTML 骨架、CSS 美學、JS 邏輯明確分離，不引入非必要的厚重套件。

## 步驟序列

### 步驟一：視覺原型與核心卡片建立（Visual Core & Immediate Dopamine）

- **目的**：先做出能提供正向回饋的高擬真成果展示，確認視覺氛圍與核心資訊載體。
- **Prompt 模板**：
  ```text
  請幫我在這個前端專案中，以純原生 HTML/CSS/JS 設計一個「[應用主題，如：生活隨筆札記 / 閱讀金句摘錄 / 咖啡風味記錄]」的「[核心展示元件類型，如：社群風格圖文卡片 / 瀑布流資訊卡片]」。
  需要具備：
  1. 視覺風格：[期望視覺風格，如：沉穩低調 / 預設微軟正黑體 / 柔和圓角與陰影]，排版舒適且適配手機與桌面端。
  2. 核心資訊：包含 [作者或使用者名稱 / 相對時間 / 分類標籤 / 主要圖文內文 / 附加地點或屬性]。
  3. 互動回饋感：提供 [如：點讚跳動動畫 / 雙擊照片愛心特效 / 收藏書籤切換 / 即時回應輸入]。
  4. 示範資料：預先提供 [2~3] 筆具備真實感的情境範例，確保開箱即能看到完整視覺效果。
  ```
- **成功判斷標準**：本機直接開啟 HTML 或靜態預覽時，能看到完整、排版合宜且具備呼吸感的核心卡片，按鈕懸停或點擊有直觀的動畫反饋。

---

### 步驟二：極低摩擦的新增流程設計（Frictionless Capture Flow）

- **目的**：設計讓「最懶的使用者」也能在 10 秒內完成一次記錄的新增介面，消除發呆與猶豫成本。
- **Prompt 模板**：
  ```text
  請為這個「[應用主題]」設計一個極低操作阻力的新增彈窗/表單介面，引導使用者將隨手短想法轉化為完整卡片：
  1. 主題快速選擇：提供 [選項 A]、[選項 B]、[選項 C] 三個明確的分類選項（Radio Card），點擊即選中，免除思考分類的痛苦。
  2. 極簡輸入框：核心欄位僅需輸入 [1~2 句話的簡短想法]，輸入框附帶友善的 Placeholder 提示。
  3. 智慧潤飾輔助：提供一個「[如：風格自動排版潤飾]」按鈕，能一鍵處理 [中英文半形空格 / 全形標點轉換 / 語調收斂]。
  4. 零阻力配圖：提供「[精選推薦風格配圖一鍵點選]」與「[本機圖檔拖曳上傳與即時縮圖預覽]」兩種彈性路徑。
  ```
- **成功判斷標準**：點擊新增按鈕能優雅喚起對話框，使用者在不填寫冗長複雜設定的情況下，即可順暢完成內容填寫並提交。

---

### 步驟三：資料無感持久化與樂觀更新（Invisible Persistence & Optimistic UI）

- **目的**：在無後端伺服器架構下，確保使用者的記錄不會因重新整理頁面而遺失，並享有即時插入的流暢體驗。
- **Prompt 模板**：
  ```text
  請為目前的功能加入資料持久化與即時更新機制：
  1. 本地儲存：將使用者新增的項目與互動狀態（如：[點讚狀態與數值 / 收藏標記 / 回應列表]）同步寫入 localStorage。
  2. 初次引導：當 localStorage 為空時自動載入預設示範卡片；若使用者完全清空，需呈現友善的空狀態（Empty State）引導開始記錄。
  3. 樂觀插入：新發布的項目立即置頂於動態列表首位，並帶有平滑滾動或淡入動畫，無需重新整理頁面。
  4. 安全性：所有使用者輸入之文字在渲染至 DOM 前必須進行 HTML 轉義以防範 XSS 攻擊。
  ```
- **成功判斷標準**：新增項目後立即出現在列表最前方；按下 F5 重新整理瀏覽器後資料依然存在；空狀態與示範資料能正確切換。

---

### 步驟四：靜態部署與環境快取防禦（Zero-Trap Deployment）

- **目的**：將應用推送至靜態託管平台（如 GitHub Pages），排除 CDN 快取、路徑解析與靜態建置引擎的隱形地雷。
- **Prompt 模板**：
  ```text
  請幫我將目前的成果提交並部署至 [目標環境，如：GitHub main 分支與 GitHub Pages]：
  1. 快取穿透防禦：在 HTML 的 CSS 與 JS 引用路徑加入版本參數（如：./style.css?v=[版本號/時間戳]），並確認路徑開頭為明確的相對路徑 ./。
  2. 靜態直出標記：確保專案根目錄包含 .nojekyll 檔案，跳過 Jekyll 引擎編譯，加速靜態資源發布。
  3. 規範化提交：遵循 Conventional Commits（如 feat:、fix:、docs:）撰寫清楚的提交訊息並完成 git push。
  完成後請提供線上驗證方式與預覽網址。
  ```
- **成功判斷標準**：Git 提交紀錄清晰乾淨；線上託管網址在任何瀏覽器（包含未清除快取的環境）載入皆能正確呈現完整樣式，無 404 與破版現象。

## 常見問題處理

### 問題 1：線上預覽網址樣式看似沒有連到（文字圖片散落、無 CSS 效果）
- **成因**：GitHub Pages 與 CDN 邊緣伺服器通常具有 `max-age=600`（10 分鐘）的強快取機制。當使用者造訪過舊版網頁，瀏覽器會使用快取中舊的（甚至僅有數行的）CSS，導致新 HTML class 完全沒有套用樣式；此外若使用 `href="style.css"` 且網址末尾未帶斜線，路徑容易被解析至網域根目錄造成 404。
- **解法**：
  1. 在 `index.html` 內改用明確相對路徑並帶上快取版本查詢參數：`<link rel="stylesheet" href="./style.css?v=2026xxxx">`。
  2. 在專案根目錄建立 `.nojekyll` 檔案，避免 Jekyll 建置引擎阻礙或延遲純靜態發布。
  3. 建議使用者以 <kbd>Ctrl</kbd> + <kbd>F5</kbd>（Mac: <kbd>Cmd</kbd> + <kbd>Shift</kbd> + <kbd>R</kbd>）強制更新快取。

### 問題 2：使用者重新整理網頁後，剛剛記錄的內容全部遺失
- **成因**：僅在執行階段操作 DOM 節點，未設計本地資料存儲層（Data Access Layer）。
- **解法**：建立統一管理資料陣列的輔助函式（如 `getPosts()` 與 `savePosts()`），使用 `localStorage` 作為單一真相來源（Single Source of Truth）。每次新增、按讚或留言時，均先更新記憶體資料模型，再寫入 `localStorage`，最後重新驅動視圖渲染。

### 問題 3：AI 生成的程式碼把 HTML、CSS、JS 混在一起（產生大量 inline style 或難以維護的代碼）
- **成因**：Prompt 未對架構邊界提出嚴格要求，AI 傾向採用捷徑將樣式寫入 HTML 行內標籤中。
- **解法**：在初始指令中明訂「職責分離原則（Separation of Concerns）」：
  - `index.html`：僅包含語意化標籤（`<header>`, `<main>`, `<article>`, `<dialog>`），嚴禁行內樣式與行內 JS。
  - `style.css`：負責所有排版、顏色變數與動畫，採 kebab-case 命名，禁用 `!important`。
  - `app.js`：由 `DOMContentLoaded` 統一啟動，使用事件委派（Event Delegation）統一管理動態插入元素的互動。
