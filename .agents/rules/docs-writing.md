# 文件撰寫規範 (Documentation Writing Rules)

本規範適用於專案內所有技術文件、README、開發指南、樣式設定及各類說明文件的撰寫。

---

## 1. 寫作風格與語調

- **沉穩低調、務實求真**：
  - 專注於事實與具體實作，不講空話，不堆砌華麗辭藻。
  - 用清楚精準的文字講述「它做什麼、怎麼用、遇到問題如何解決」。
- **禁止一切浮誇形容**：
  - 嚴格禁止使用「地表最強」、「革命性突破」、「極致優雅」、「無可挑剔」等浮誇宣傳口吻。
  - 好東西用過就知道，不需要我們自己吹捧。
- **微量且克制的幽默**：
  - 可以偶爾加入一點乾淨、內斂的幽默感（例如：提醒大家不要把密碼 commit 上去之類的善意自嘲）。
  - 幽默感是提味用的黑胡椒，撒一點就好，別把整碗麵變成胡椒湯。

---

## 2. 字型設定規範

- **預設字型**：若未特別指定字型，一律優先採用**微軟正黑體**。
- **CSS / 網頁設定建議**：
  ```css
  font-family: "Microsoft JhengHei", "PingFang TC", "Helvetica Neue", sans-serif;
  ```
- **文件輸出設定**：若匯出 PDF、Word 或投影片，預設字體一律設定為「微軟正黑體 (Microsoft JhengHei)」。

---

## 3. 語言與排版規範

- **主要語言**：使用繁體中文（台灣習慣用語）。
- **中英文空格**：中文與半形英文字母、數字之間保留一個半形空格（例如：`使用 Git 進行版本控制`、`支援 Node.js 18+`）。
- **標點符號**：
  - 中文段落內使用全形標點符號（`，`、`。`、`！`、`？`、`：`、`；`）。
  - 英文縮寫或專有名詞內維持半形標點（例如：`e.g.`、`v1.0.0`）。
- **專有名詞大小寫**：嚴格遵守官方標準大小寫與拼寫，避免隨意簡寫或大小寫混淆：
  - 正確：`GitHub`、`JavaScript`、`HTML`、`CSS`、`Git`、`Markdown`
  - 錯誤：`Github`、`javascript`、`GIT`

---

## 4. Markdown 結構規範

- **標題層次 (Headings)**：
  - 一篇文件只應有一個最高層級標題（`#` 一級標題）。
  - 標題依層級遞進（`#` -> `##` -> `###`），禁止跳級使用。
- **程式碼區塊 (Code Blocks)**：
  - 必須標註相應的語言標籤（如 `bash`、`javascript`、`html`、`css`、`json`、`markdown`）。
  - 終端機指令與輸出結果分開表示，命令列開頭避免多餘的手動 `$` 符號（方便讀者一鍵複製）。
- **清單與條目**：
  - 無序清單統一使用 `-` 開頭。
  - 步驟或有順序關聯的項目一律使用數字有序清單（`1.`、`2.`、`3.`）。

---

## 5. 內容維護原則

- **目標明確**：文件開頭以 1~2 句話簡要說明本文件之目的與適用對象。
- **條理清晰**：長篇內容必須善用小標題、表格、引言（Blockquote）或項目符號條理化整理。
- **步驟可驗證**：操作指南需給出明確的前置需求、執行指令以及預期產出/驗證方式。
- **維持更新**：當程式碼、架構或指令調整時，必須同步更新對應的文件內容，避免出現過時資訊。
